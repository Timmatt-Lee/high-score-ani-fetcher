# Repository-Specific Rules: high-score-ani-fetcher

This file defines the project-specific rules for the `high-score-ani-fetcher` repository. These rules override or extend the global rules specified in `~/.gemini/GEMINI.md`.

## 1. PR, Review & Merge Lifecycle (Override)

For this repository, we strictly follow the default PR lifecycle in `GEMINI.md`:

- Create the PR with auto-merge enabled.
- All review iterations occur via the IDE Chat UI rather than GitHub comments.
- The PR merges automatically once approved on GitHub.
- Branch cleanup is automated via GitHub's repository settings.

## 2. Visual / Screenshot Testing Rules (MANDATORY)

- **Strict Automated Visual Enforcement**:
  - A validator script [verify-visual-coverage.ts](file:///Users/timmatt/Desktop/high-score-ani-fetcher/scripts/verify-visual-coverage.ts) is configured at the root of the project to check if any UI component is missing a corresponding Storybook file.
  - This check is integrated into `npm run build`, `npm run test`, and the `.husky/pre-push` hooks. Any missing `.stories.tsx` files for a component will immediately break the build, test run, or push pipeline.
- **Comprehensive Visual Coverage**:
  - Whenever you modify styles (CSS), layouts (HTML/JSX), or interactive frontend components, you **MUST** create or update corresponding Storybook stories or visual regression tests.
  - You MUST capture every possible state of the component (such as: loading, empty, success, error, disabled, active, hover) and represent all major Critical User Journeys (CUJs).
  - Never leave any screen state unrepresented in the visual suite.
